### 1. 本地回测引擎 (执行模块)

**原始需求**：
```
实现本地的模拟交易逻辑，包括手续费，下单，止盈止损
```

**当前状态**：
- ❌ 没有BacktestExecutor实现
- ❌ 没有模拟订单撮合
- ❌ 没有模拟手续费计算

**影响**：
- 无法使用历史数据测试策略
- 只能在实盘/测试网验证

**建议**：
创建 `internal/execution/backtest/simulator.go`

---

### 2. 订单簿功能 (数据模块)

**原始需求**：
```
获取订单簿(<symbol>@depth<levels>)，推送到下游模块，保存到数据库
```

**当前状态**：
- ❌ 没有订单簿WebSocket订阅
- ❌ 没有订单簿数据结构
- ❌ 没有订单簿存储

**影响**：
- 基于订单簿的策略无法实现
- 无法做微观市场分析

**建议**：
在 `internal/dataManager/v2/` 添加 `orderbook.go`

---

### 3. WebSocket账户推送 (执行模块)

**原始需求**：
```
接受关于账户信息、仓位情况和委托情况的websocket推送
```

**当前状态**：
- ⚠️ 只有REST API查询
- ❌ 没有WebSocket User Data Stream

**影响**：
- 仓位变化延迟
- 需要轮询查询（浪费API配额）

**建议**：
在 `internal/execution/binance/` 添加 `user_stream.go`

---

### 4. 结构化日志 (监控模块)

**原始需求**：
```
实现结构化日志，支持多级别，集中收集
```

**当前状态**：
- ⚠️ 只有标准库log.Printf
- ❌ 没有日志级别控制
- ❌ 没有结构化字段

**影响**：
- 日志难以搜索和分析
- 无法做日志聚合

**建议**：
创建 `internal/observability/logger.go`，使用 `zap` 或 `zerolog`
